# {{ $frontmatter.title }}

<time>{{ $formatDate($frontmatter.date) }}</time>

Release 0.50.0 fixes a security problem in test-file handling and several cases where report consumers saw different results from the console. It also makes random-order replay simpler and removes the interactive tutorial.

## Test filenames are no longer evaluated as shell code

The per-test exit trap used to embed the test-file path in a string that Bash evaluated again when the trap ran. A filename containing a command substitution could therefore execute that command. This matters when CI checks out a branch whose filenames another contributor controls ([#1315](https://github.com/TypedDevs/bashunit/issues/1315)).

The trap now treats the path as data. Such filenames no longer cause their tests to skip assertions and appear as risky results. Update projects that run tests over files from untrusted branches.

## Replay a shuffle with just its seed

`--seed` now implies random order. Copying the seed from a failing run is enough to replay the shuffle, unless you explicitly select another order ([#1287](https://github.com/TypedDevs/bashunit/issues/1287)).

```bash
bashunit --seed 12345 tests/
```

Snapshot updates also have a shorter spelling, `-u`:

```bash
bashunit -u --filter test_render_status tests/
```

## Reports agree with the run

JSON and JUnit output no longer receive stray console text from empty parallel selections, script teardown, duplicate-function errors or worker stderr. Parallel reports count a file-level hook failure once, matching the console summary ([#1295](https://github.com/TypedDevs/bashunit/issues/1295), [#1297](https://github.com/TypedDevs/bashunit/issues/1297), [#1299](https://github.com/TypedDevs/bashunit/issues/1299), [#1301](https://github.com/TypedDevs/bashunit/issues/1301)).

JUnit and Cobertura escape special characters in paths. Streaming TAP escapes `#` in descriptions, GitHub Actions annotations encode their property values, and a code fence in a failure message cannot truncate the Markdown summary. Benchmark files that fail to load or set up now make `bashunit bench` exit non-zero.

The recorded parallel reporting workload runs about 1.9 times faster and uses about 1.8 times less CPU after removing repeated base64 processes. Startup also saves about 9 ms in the recorded measurement by loading the colour palette without a subprocess for each colour ([#1289](https://github.com/TypedDevs/bashunit/issues/1289), [#1285](https://github.com/TypedDevs/bashunit/issues/1285)).

## Tutorial removal

`bashunit learn` has been removed. Calling it explains the removal and points to [the documentation](/installation). Use the guides for learning and examples; the runner no longer ships the interactive tutorial subsystem.
