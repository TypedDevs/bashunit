Release 0.46.0 makes it easier to choose a run, investigate intermittent failures, and publish results in CI. It also fixes reports that could contain zero tests after a parallel run.

## Inspect and select a run

`--changed` selects test files Git reports as touched since a reference, including staged, unstaged, and untracked changes. It selects changed test files, rather than finding every test affected by a source-code change. Use `--list` to inspect the selected tests without executing them ([#1010](https://github.com/TypedDevs/bashunit/issues/1010), [#1007](https://github.com/TypedDevs/bashunit/issues/1007)).

```bash
bashunit tests/ --changed origin/main --list
bashunit tests/ --list --list-format json
```

Tag expressions support AND and NOT, while repeated `--tag` options keep their OR behavior. `--exclude-filter` excludes matching test names and takes precedence over inclusion. `--order-by defects` brings the previous run's failures to the front while still running the entire selected suite.

## Look for intermittent failures

`--repeat` runs every selected test several times, reports an aggregate result, and identifies the failed iteration. Retry-assisted passes are now counted as flaky, with the first failure included in reports. They remain inside the pass total unless you request `--fail-on-flaky` ([#1013](https://github.com/TypedDevs/bashunit/issues/1013), [#1012](https://github.com/TypedDevs/bashunit/issues/1012)).

```bash
bashunit tests/ --repeat 20 --filter flaky_candidate
bashunit tests/ --retry 2 --fail-on-flaky
```

## Bring useful reports into CI

JSON, TAP, HTML, and JUnit file reports now collect results correctly under `--parallel`. JUnit groups tests by file, includes captured output, and carries informative failure messages. Markdown summaries can populate the GitHub Actions step summary, and automatic Actions annotations point to the failing file and line ([#1004](https://github.com/TypedDevs/bashunit/issues/1004), [#1016](https://github.com/TypedDevs/bashunit/issues/1016)).

Coverage gains Cobertura XML and `--coverage-diff`, which limits the coverage view and minimum-percentage check to changed lines:

```bash
bashunit tests/ --coverage --coverage-diff origin/main --coverage-min 90
```

Coverage processing also avoids a process per classified source line. New numeric-range and command-availability assertions round out the release, alongside clearer handling of malformed numeric values and custom-assertion failures.
