Release 0.48.0 improves coverage speed and the errors that explain why a run did not execute as expected. It also fixes cases where parallel execution could report success while silently missing tests.

## Faster coverage and HTML reports

Coverage processing avoids repeated work when reading hits and classifying source lines. In the repository's recorded measurements, a coverage run fell from 16.2 seconds to 2.9 seconds, while generating an HTML report for 128 files fell from 58.7 seconds to 3.1 seconds ([#1092](https://github.com/TypedDevs/bashunit/issues/1092), [#1117](https://github.com/TypedDevs/bashunit/issues/1117)). Those are measurements of those workloads, rather than a promised speedup for every project.

The HTML test report now includes a Failures section with the test name, source location and message. Its summary includes risky and flaky outcomes, and test titles are escaped before they enter the markup ([#1251](https://github.com/TypedDevs/bashunit/issues/1251), [#1252](https://github.com/TypedDevs/bashunit/issues/1252), [#1249](https://github.com/TypedDevs/bashunit/issues/1249)). Coverage reports also handle filenames containing `|`, `<` or `&`.

On Bash 3.x, `--verbose` explains that coverage cannot count lines executed inside subshells. Hits inside command substitutions are preserved on supported newer shells, so their work no longer disappears from the result ([#1112](https://github.com/TypedDevs/bashunit/issues/1112), [#1101](https://github.com/TypedDevs/bashunit/issues/1101)).

## Missing tests become visible failures

Duplicate test functions are detected in parallel runs again. An undefined data provider, or one that returns no rows, now produces an error naming the provider instead of making the test vanish behind “No tests found” ([#1147](https://github.com/TypedDevs/bashunit/issues/1147), [#1145](https://github.com/TypedDevs/bashunit/issues/1145)).

Bootstrap failures exit non-zero wherever a bootstrap is loaded. A report destination that is a directory fails with a clear message, and a benchmark path with no benchmarks also exits non-zero. These failures can now reach CI instead of looking like a passing run.

## Output that other tools can read

JUnit output is valid XML, and stopping a parallel run after a failure no longer inserts console text into a machine-readable stream. TAP escapes `#` in test names so a name containing `# SKIP` is not mistaken for a directive ([#1239](https://github.com/TypedDevs/bashunit/issues/1239), [#1243](https://github.com/TypedDevs/bashunit/issues/1243), [#1119](https://github.com/TypedDevs/bashunit/issues/1119)).

For test authors, `assert_exec` can check an expected non-zero exit under `--strict`, literal backslashes survive comparison normalization, and a provider argument ending in a backslash reaches the test intact. The reference docs now explain lowercase `test_` names, positional installer arguments and how to give each provider row its own named snapshot.
